# OIDC client requirement map

This SA04 slice maps OIDC Discovery and the authorization-code client path,
including all 13 numbered ID-token validation steps, UserInfo and refresh.
The references are the official [Core 1.0](https://openid.net/specs/openid-connect-core-1_0.html)
and [Discovery 1.0](https://openid.net/specs/openid-connect-discovery-1_0.html)
publications incorporating errata set 2, checked on 2026-11-19. Clause topics
below index the source text; they do not restate every normative condition.

Runtime references were inspected at
`a009f5cf` (`test(keycloak): verify real JWKS revalidation across key rotation`).
The [FAPI map](requirements.md) covers its separately configured profile.
The [OAuth map](requirements-oauth.md) and
[JWT/Message Signing map](requirements-jwt-signing.md) account for their own
client duties. SA04 remains partial: the remaining OAuth extension/security
clauses and optional features listed below need narrower reviews before an
implementation claim includes them.

Test links identify existing scenarios, not new executions. The
[scope map](scope.md) records selected OIDF modules and application outcomes;
the [release review](release-review.md) retains their actual revisions and
limitations. [Source identity](source-identity.md) qualifies subsequent schema-4
runs. A test definition, historical schema-3 report or one successful selection
does not establish a complete source-qualified release matrix. SA08 owns that
matrix and retained evidence. Nothing here establishes certification.

The relying party (RP) is the package plus its calling application. The OpenID
Provider (OP) owns its authentication, consent, registration records and token
issuance. Operators own authoritative issuer selection, external callback
routes, TLS termination, clocks and credential custody. Those duties cannot be
proved solely by a local client test.

## ID-token validation steps

All numbered rows refer to [Core 3.1.3.7](https://openid.net/specs/openid-connect-core-1_0.html#rfc.section.3.1.3.7).
The RP configuration is normal signature/identity validation unless the row
identifies an optional feature. Required claim presence/types also follow
[Core 2](https://openid.net/specs/openid-connect-core-1_0.html#rfc.section.2);
I checks issuer, scalar subject, audience and finite temporal values before
credentials become authenticated identity.

| Step / topic | Responsible role and selected behavior | Concrete evidence | Remaining limit or policy distinction |
| --- | --- | --- | --- |
| 1, encryption | RP, conditional on negotiated encryption | I explicitly detects and rejects encrypted ID tokens; [test-jwt-jwe-detection.R](../../tests/testthat/test-jwt-jwe-detection.R) verifies fail-closed behavior | Encrypted ID-token decryption is unsupported. General JWE helpers used for JAR/JARM do not establish this feature. Configure signed-only ID tokens. |
| 2, issuer | RP; exact generic issuer | I compares the validated token issuer to the configured/discovered expected issuer; Basic invalid-issuer case and refresh issuer tests | Microsoft tenant-independent issuer templates are a provider-specific extension with separate policy/tests, not a relaxed generic issuer rule. |

## Refresh

The numbered bullet references below index the eight response conditions in
[Core 12.2](https://openid.net/specs/openid-connect-core-1_0.html#rfc.section.12.2).
Their issuance duties belong to the OP; R describes the RP checks that can
establish consistency before replacement credentials become usable.

| Clause / topic | Responsible role and configuration | Concrete evidence | Remaining limit or action |
| --- | --- | --- | --- |
| [12.1](https://openid.net/specs/openid-connect-core-1_0.html#rfc.section.12.1), refresh request | RP; token endpoint form POST with configured registration method | R constructs refresh grants using existing endpoint-auth/TLS helpers; refresh-token and authentication regressions inspect the resulting path | OP ownership/authentication checks are server duties. Sender-key/certificate binding and rotation need the separate lifecycle evidence in the FAPI map. |
| [12.2](https://openid.net/specs/openid-connect-core-1_0.html#rfc.section.12.2), omitted ID token | RP; preserved validated original login | R retains the original ID token when omitted; malformed supplied values fail in [test-id-token-response-types.R](../../tests/testthat/test-id-token-response-types.R) | Omission is not an ID-token validation failure. | 12.2 bullet 1, issuer | OP issues; RP compares | R compares exact original issuer; OIDF invalid-issuer refresh module and validated/non-validated-path package regressions | Partial parsed-continuity checks with full signature validation disabled do not earn authenticated replacement identity credit. |
